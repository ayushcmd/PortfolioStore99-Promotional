# Security Policy

Thank you for helping protect PortfolioStore 99 and its visitors.

## Scope and supported material

This public repository contains **promotional documentation, architectural specifications, and marketing assets**. It does not contain the production storefront application or commercial template source code. The production application is maintained separately in a private repository.

Security reports involving public documentation (for example, exposed credentials, sensitive information, or unsafe instructions) are in scope here. Reports concerning the live storefront, payment processing, customer accounts, or file delivery should be sent privately to the maintainers; **do not** publish exploit details or customer information in this public repository.

Maintainers prioritize the current default branch and the live storefront. No support or fix schedule is guaranteed for older versions, unofficial copies, or third-party deployments.

## Report a vulnerability privately

Please **do not open a public GitHub issue or pull request with vulnerability details**.

Send a private report to the contact already published by PortfolioStore 99:

**[portfoliostore99@gmail.com](mailto:portfoliostore99@gmail.com)**

Use a descriptive subject such as `Security report — PortfolioStore 99`. If you prefer GitHub Private Vulnerability Reporting, check the repository's [Security Advisories](https://github.com/ayushcmd/PortfolioStore99-Promotional/security/advisories) page for a **Report a vulnerability** option. **Its enabled status has not been verified**, so email is the documented fallback.

Include only information needed to investigate:
- A concise description of the issue and potential impact
- The affected repository file, page, service, or workflow
- Reproduction steps using accounts and data you own or are authorized to test
- Sanitized logs, screenshots, or example payloads
- Suggested mitigations, if known

Do not include live secrets, payment details, order records, personal customer information, or other people's credentials. Ask the maintainer to arrange an appropriately secure transfer channel if sensitive evidence is essential.

## Proposed response expectations — owner review required

**These are proposed targets, not a confirmed service-level commitment.** The repository owner should approve or revise them before merging.

| Stage | Proposed target |
| --- | --- |
| Acknowledgment | Within 3 business days of receipt |
| Initial assessment | Within 7 calendar days after acknowledgment |
| Follow-up on confirmed reports | Approximately every 14 days, where practical |
| Coordinated public disclosure | Discuss an appropriate date after remediation; 90 days can be a starting point, not a fixed deadline |

Resolution times vary with severity, reproducibility, and dependencies. There is no guaranteed fix date.

## Responsible disclosure

- Test only assets, accounts, and data you own or have explicit permission to assess.
- Avoid disruption, destructive testing, fraud, social engineering, or excessive requests.
- Stop if you encounter private information, and report the finding privately.
- Give maintainers an opportunity to investigate and coordinate remediation before publishing technical details.
- Do not share credentials, customer information, or unreleased commercial source code.

For routine documentation corrections and non-security problems, use [GitHub Issues](https://github.com/ayushcmd/PortfolioStore99-Promotional/issues) instead.
